# ADR-015: Read-only Runtime Event Adaptation

## Status

Pending architecture review.

## Context

Level 18 introduces a canonical representation of caller-supplied runtime observations.
The representation must preserve the certified boundary in which the existing runtime
is the sole execution authority.

## Decision

A runtime event is identified by the tuple `(source_id, sequence_id, event_id)` and
also carries an event type, timezone-aware occurrence time, and non-empty canonical
JSON payload. The tuple is the adaptation identity; `event_id` alone is not asserted
to be globally unique. Sequence identifiers are non-negative integers scoped to one
`source_id`. Replay rejects duplicate sequence identifiers within one supplied source
stream and orders that stream by sequence identifier.

The canonical adapter maps an immutable event to verifiable evidence. Adaptation is
read-only, deterministic, preserves the event timestamp, and records
`execution_authority=existing-runtime` and `evidence_only=true`. Adapter registration
rejects adapters that do not declare the read-only/evidence-only boundary.

## Public contract versioning

The current public contract is the unversioned Level 18 baseline. Compatibility is
therefore exact: field names, validation, canonical serialization, digest rules,
identity construction, and ordering semantics must not change silently. Any breaking
change requires a new explicit contract version, migration/replay rules, acceptance
fixtures for both versions, and architecture approval. Package-version changes alone
do not change this contract.

## Consequences and boundaries

Integrity proves deterministic representation of supplied input, not source
authenticity, capture completeness, delivery, or execution. This decision adds no
polling, command, trading, enforcement, persistence, signing, scheduling, migration,
or authority-transfer capability. Level 19 is not authorized by this ADR.
