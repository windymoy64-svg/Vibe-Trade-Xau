# ADR-000: Immutable Foundation Contracts

## Purpose

Record the stable contract primitives already used by the AIOS foundation.

## Decision

Foundation values are modeled as immutable, extra-field-forbidding contracts.
Identifiers are normalized and portable; timestamps are timezone-aware; runtime
references may be pinned by semantic identity and SHA-256 digest. Contracts are
deterministically serializable and are not execution mechanisms.

Evidence includes `src/aios/contracts/identifiers.py` and
`src/aios/contracts/runtime_manifest.py`.

## Alternatives

- Mutable dictionaries shared across subsystems.
- Storage paths or process-local IDs as identity.
- Unpinned dependency names resolved during execution.

## Tradeoffs

Strict validation and immutability add construction overhead and require schema
evolution. In return they reduce accidental mutation and make evidence stable.

## Consequences

Consumers must create new values rather than mutate existing contracts. Invalid
or non-portable identifiers and malformed digests fail validation.

## Scope

Phase 0 foundation contracts only. No runtime provisioning, execution, policy
enforcement, or migration is implied.
