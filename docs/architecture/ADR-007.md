# ADR-007: Read-Only Integration Snapshots

## Purpose

Record the integration boundary used to capture existing runtime observations.

## Decision

Integration adapters accept externally supplied observations and convert them
to immutable, deterministic runtime snapshots. Snapshots identify their
authority, support digest chaining through `previous_digest`, and can be bridged
to content-addressed evidence. Comparison is exposed as a protocol over mappings.
Adapters do not call, mutate, or control the observed runtime.

Evidence includes `agent/src/integration/runtime_snapshot.py`,
`runtime_adapter.py`, `comparison_port.py`, and `evidence_bridge.py`.

## Alternatives

- Direct two-way integration with runtime internals.
- Shared mutable state between old and new foundations.
- Comparison embedded in the execution path.

## Tradeoffs

Snapshot boundaries reduce coupling and side effects, but freshness and capture
correctness depend on the external producer.

## Consequences

Integration remains read-only and evidence-oriented. Snapshot authority labels
must be retained when evidence is exported.

## Scope

Phase 7 integration ports and adapters only. No command path or migration.
