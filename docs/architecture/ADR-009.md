# ADR-009: Retain Existing Runtime Authority and Migration Boundary

## Purpose

Record the repository’s current cutover boundary after the completed foundation
phases.

## Decision

The existing/legacy runtime remains the sole execution authority. AIOS policy,
runtime supervision, integration snapshots, and shadow reports remain
non-authoritative and evidence-only. No migration, dual-write, routing cutover,
or replacement is part of the implemented foundation.

Evidence is explicit in policy comparison (`runtime_authority: legacy`), runtime
supervision (`executable=false`, `authoritative=false`), research manifests, and
shadow coordination (`execution_authority: existing-runtime`).

## Alternatives

- Immediate replacement of existing runtime behavior.
- Partial cutover before audit acceptance.
- Silent fallback between execution authorities.

## Tradeoffs

Retaining one authority avoids split-brain behavior and preserves the approved
runtime baseline. It also leaves the architecture audit blockers unresolved.

## Consequences

Any future migration requires explicit approval, measurable parity criteria,
rollback design, and a new ADR. Until then, foundation outputs cannot execute or
enforce.

## Scope

Phase 9 boundary declaration. No migration is authorized by this ADR.
