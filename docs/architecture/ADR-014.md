# ADR-014: Deterministic Evidence-Layer Integration and Validation

## Purpose

Compose the approved Foundation and Phase 10–12 evidence layers into one deterministic
pipeline suitable for architecture validation and System Integration Testing review.

## Decision

Phase 13 accepts immutable scenario specifications containing evidence, exact trust
policy snapshots, observation source metadata, explicit timestamps, expected counts,
and optional replay-outcome evidence. A pure builder derives verification manifests,
sealed observations, archive entries and batches, an audit chain, archive verification,
analytics, and read-only dashboards. Inputs are canonically ordered by caller-supplied
timestamps and stable identifiers; no wall clock or implicit repository state is used.

Cross-layer validation checks session, metrics, dashboard, manifest, archive, audit,
analytics, replay, and integration-dashboard consistency. Findings are immutable,
deterministically ordered, and fail closed. Analytics refresh recomputes projections
from captured artifacts only and performs no polling, scheduling, or I/O.

## Boundaries

The pipeline is evidence-only and non-authoritative. It has no execution, enforcement,
trading, broker/exchange, scheduler, persistence, database, migration, signing,
consensus, or authority-transfer capability. The existing runtime remains the sole
execution authority.

## Consequences

Successful validation proves internal consistency of supplied artifacts, not external
completeness, durability, liveness, authenticity beyond approved policy verification,
or production readiness. Stress checks validate deterministic behavior at increasing
fixture sizes but are not performance benchmarks.

## Scope

Level 15, Phase 13 only. Phase 14 is not authorized by this decision.
