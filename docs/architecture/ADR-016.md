# ADR-016: Evidence-only Runtime Integration Harness

## Status

Pending architecture review.

## Context

Level 19 composes Level 18 validation and adaptation for caller-supplied batches while
retaining rejected-input evidence and deterministic replay.

## Decision

The harness creates immutable sessions and reports. Session identity binds the exact
adapter, opening time, expected input count, and ordered input set. Input order is part
of session identity; accepted events are exposed in sequence order. Validation and
conversion failures are recorded per input and do not abort unrelated inputs.

Replay is permitted only with the adapter identified by the report and compares
recomputed evidence with the recorded report. It performs no source read or external
side effect. Duplicate sequence identifiers in the supplied source stream fail closed.

## Semantics

Counts describe only the supplied batch: accepted, rejected, validation-failure, and
conversion counts make no statement about events omitted before ingestion. A
successful replay proves deterministic reproduction from the retained report inputs;
it does not prove original capture completeness or source authenticity.

## Public contract versioning and boundaries

The Level 19 baseline follows the versioning rule in ADR-015. Breaking session,
outcome, replay, canonicalization, or digest changes require an explicit new contract
version and architecture approval. The harness is evidence-only and does not poll,
subscribe, acknowledge, persist, remediate, execute, trade, schedule, or mutate the
existing runtime. Level 20 is not authorized by this ADR.
